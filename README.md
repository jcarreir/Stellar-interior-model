# Stellar-interior-model
 Stellar interior model

Throughout this project, a numerical model will be developed to simulate a stellar interior.
Specifically, the structure of a massive star on the main sequence, characterized by a convective
core and a radiative envelope, will be studied. The model will start with known values of mass and
chemical composition and will integrate the fundamental equations that govern the behaviour of
plasma.

The process will involve integration from the star’s surface inward and from the centre outward,
adjusting the boundary between the convective core and the radiative envelope to ensure a smooth
transition between them. This will require adjusting the values of the central temperature, total
luminosity, and total radius, which are initially unknown.

The project consists of five main files:
1. **main.py**: This is the main script that runs the numerical model. Here, classes, functions, and constants defined in other files will be imported to keep the code written in this file as clear and clean as possible.
2. **config.py**: This file contains the initial values for the total mass and chemical composition of both the star and the test model used to validate the calculation. Additionally, it contains the central temperature, total radius, and total luminosity values needed to initialize the calculations. It also includes some universal physical constants and the maximum error value allowed in the integration algorithm.
3. **star_class.py**: Defines the class and methods that represent different aspects of the stellar interior. This file stores all the numerical resolution of the stellar interior.
4. **model.ipynb**: A Jupyter notebook that allows running the model interactively. Its content is identical to that of the main file but with the advantage of being able to visualize the model results, perform step-by-step analysis, and easily conduct tests.
5. **HR_diagram.ipynb**: A small Jupyter notebook that allows graphical representation of the star in a Hertzsprung-Russell diagram along with known stars of similar characteristics.

### StellarModel
The **StellarModel** class is the core of the project and consists of the following methods:

- **Constructor**: All classes must have a constructor whose purpose, in this case, is to initialize all the fundamental parameters of the star. In particular, the mass values, hydrogen and helium fractions, central temperature, total luminosity, and total radius are assigned. Additionally, auxiliary methods **initialize_parameters** and **initialize_arrays** are called to have all the necessary values available for equation resolution and to initialize empty vectors that will store the values of the variables and their gradients.
- **reversal**: This method allows us to invert the vectors that store the variables and change the sign of the integration step. It is very useful for changing the integration direction easily when switching from integrating from the surface to the center or vice versa. It only takes a string argument indicating the direction in which the process is being carried out.
- **delta_1** and **delta_2**: Perform first and second-order finite differences necessary to execute the algorithm.
- **energy_generation_rate**: Calculates the energy generation rate and the exponent ν as a function of temperature and pressure using equation 9. It consists of two other functions, **pp_chain** and **CNO_cycle**, which handle the calculation depending on whether the energy generation is carried out by the proton-proton chain or the CNO cycle, respectively, comparing which of the two mechanisms is dominant.
- **three_layers_surface**: Responsible for calculating the first three layers in the integration from the surface. The value of the variables in each layer is stored in their corresponding vector. It is important to note that the start does not take place exactly at the surface but at 0.9 * RT to avoid convergence issues. At this step, it is assumed that mass and luminosity are practically constant and equal to their maximum values. These layers serve as a basis for calculating the corresponding gradients in the following steps and continuing with the algorithm.
- **radiative_envelope**: Method responsible for executing the algorithm corresponding to the radiative envelope, taking the third layer as the starting point and integrating inward until the transport parameter reaches its critical value, n + 1 = 2.5, as previously mentioned. When this happens, the calculation will stop, and the layer number where the transition takes place will be stored. Additionally, in this last layer, the polytropic constant K' value used in the convective core region is calculated.
- **convective_core**: Carries out the calculations for the layers corresponding to the convective core using the appropriate algorithm. It can be used for both integration from the surface and integration from the center. Therefore, it is necessary to specify which of the two situations we are in. When integrating toward the center, it will stop upon reaching it, while its execution from the center toward the surface stops upon reaching the layer where the transition occurs.
- **transition_layer_down** and **transition_layer_up**: Calculate the variables in the transition region. Since the layers have a thickness h, it is most likely that the transition does not take place exactly at the edge of any of them, so its position is calculated more precisely by linear interpolation. As their operation differs slightly depending on the integration direction, we have created two different functions for each case.
- **three_layers_core**: Calculates the first three layers in the integration from the center. The value of the variables in each layer is stored in their corresponding vector.
- **calculate_relative_errors**: Takes the variable values at the transition between the radiative envelope and the convective core and calculates the total relative error. The goal is to keep this error as low as possible to have a smooth transition between both regions and obtain a physically acceptable model.
- **extra_layers**: Allows us to calculate the most superficial layers corresponding to the region between 0.9RT and RT that we were missing by using the same equations applied to integrate the first three surface layers, but this time in an outward direction until reaching RT.
- **complete_model**: This is the method we will use to build the complete model. It makes use of all the previous ones in the following way:
  1. It starts with a call to **reversal** to ensure that the vectors have their components in the correct order and that the integration step value h is negative so that the integration is carried out toward the center from the surface.
  2. Next, the **three_layers_surface** and **radiative_envelope** functions are executed to integrate from the surface to the transition layer between the radiative envelope and the convective core. The **radiative_envelope** function returns an integer corresponding to the last calculated layer.
  3. The next step is to call the **convective_core** function, providing the layer number obtained in the previous step and specifying 'surface' since we are integrating from the surface to the center. The calculation will stop upon reaching R = 0.
  4. After that, the **transition_layer_down** function is executed to obtain the exact transition point between the convective and radiative zones. The variable values are stored to be used later to calculate the total relative error.
  5. Now, we need to prepare for integration from the center. To do this, we start by reversing the vectors that store the variables and changing the sign of h using the **reversal** function, passing 'center' as an argument.
  6. Integration from the center begins with **three_layers_core**, which also returns an integer with the number of the last calculated layer, which will always be the third in this case.
  7. To continue integration toward the surface, **convective_core** is executed again, providing the previous layer number and specifying 'center'. Additionally, in this case, the calculation stops upon reaching the R value where the transition layer calculated earlier is located, so this value is also passed as an argument. As in the integration from the surface, it will return an integer with the number of the last calculated layer.
  8. The next step is to calculate the variable values in the transition layer in this integration from the center, so the **transition_layer_up** function is called, providing the R value where it is located and the integer obtained in the previous step for interpolation.
  9. At this point, we already have the variable values in the transition region integrating in both directions, so it is not necessary to continue the calculations toward the surface. We simply verify the matching condition, which translates into a call to the **calculate_relative_errors** function.
  10. Finally, the **extra_layers** function is called to compute the most superficial layers and add them to the vectors that store the variables. In this outer region, the layers are calculated using convective transport.
- **optimal_temperature_calculation**: This function allows us to obtain the optimal central temperature value so that the total relative error is minimal. Its operation is simple as we only need to provide a list of central temperature values in which to search for the minimum. For each of these values, **complete_model** is executed and stores the error in a vector, from which the minimum will then be identified.
- **plot_array_error**: This function takes the error vector generated by the previous function and generates a graph representing the error as a function of the central temperature used, allowing us to visualize if the interval used is adequate.
- **optimal_grid_calculation**: Responsible for creating a grid of models for a specific range of total luminosity and total radius to find the values that minimize the total relative error. For each combination of RT and LT, the **optimal_temperature_calculation** function is executed since the optimal central temperature value may change slightly as the other parameters vary, and the error is stored in a matrix in which the minimum will be identified.
- **plot_matrix_error**: This function takes the error matrix generated by the previous function and graphically represents the error for the model grid, allowing us to visualize if the studied region contains a local minimum.
- **extra_variables_calculation**: This module calculates the density and energy generation rate variables to have them available in the complete model for storage or representation.
- **plot_normalized_variables**: Allows us to generate graphs showing the evolution of the variables of interest as a function of mass or radius of our choice. We have the option to display them all together in a single graph normalized to their maximum value as well as show them individually.
- **save_data**: Once the model has been generated, this function allows us to export the data to a .csv file for storage and later use.
